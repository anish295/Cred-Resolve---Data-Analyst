Data Contracts & Design Decisions

Primary Keys

  • golden_payments: payment_id
  • golden_calls: call_id
  • golden_agents: employee_code
  • golden_sessions: session_id
  • golden_account_snapshot: account_id + snap_month

Incremental Processing

  • Watermark: MAX(event_at) per table
  • New rows appended daily
  • Late-arriving data: 72h reprocess window
  • Backfill: full rerun with --backfill flag
  • Idempotent: INSERT OR REPLACE on PK

Late-Arriving Data

  • Payments: up to 48h delay from gateway
  • Field visits: up to 24h offline sync delay
  • WhatsApp reads: delivered async
  • Treatment: reprocess last 72h each run
  • Alert if event_at - ingested_at > 48h

Data Quality Checks

  • Null rate < 5% per critical column
  • Duplicate payment_reference = 0
  • event_at must be < NOW() + 1h
  • Amount must be > 0
  • Agent in canonical agents table

Metric Definitions (locked)

  • Recovery: SUCCESS golden payments only
  • Contact: ANSWERED >30s / targeted
  • PTP: std code, excl PENDING denom
  • Channel conv: 7-day window, post-touch
  • Agent-hr: capped at 24h/session

Data Lineage

  • Every metric traces to golden table
  • Every golden row traces to raw source
  • Cleaning rules documented in SQL comments
  • Excluded rows logged to audit table
  • Schema version tracked per source

Monitoring & Anomaly Detection

Volume Checks

  • Daily call count ±30% vs 30d avg
  • Daily payment count ±20%
  • New accounts in targeting
  • Agent session hours ±25%

Quality Checks

  • Duplicate payment_ref count = 0
  • Null rate per critical column
  • Unknown disposition codes
  • TZ distribution shift

Metric Alerts

  • MoM recovery < -20%
  • Contact rate < 15%
  • PTP kept rate < 25%
  • Raw vs golden gap > 5%

SLA

  • Pipeline: runs by 6am daily
  • Dashboard refresh: hourly
  • Backfill SLA: < 4h
  • Incident escalation: < 2h
